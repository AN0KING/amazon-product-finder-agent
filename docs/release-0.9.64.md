# v0.9.64：后台补算未完成利润

后台采集巡检增加本地利润补算，每分钟最多检查一次当前任务的全部已保存商品，不限于页面可见行。主服务由看门狗恢复后，该检查也随服务启动；任务已完成、人工暂停或等待访问验证时，只补算本地数据，不恢复网络采集。

- 遗留的空利润率、缺少计算结果会使用现有统一利润模型补算并保存，通知打开的页面同步。
- 缺重量的 FBA 商品采用已有最低重量档暂估规则，结果保留估算标识；真实重量不被假定值覆盖。缺采购成本时沿用原有零成本初估标识，不伪造采购报价。
- 缺售价、明确无效的重量、缺 FBM 配送费等仍保留具体待补原因，不能强行产生利润率。
- 仅写入利润率、利润额、总成本、计算明细和待补原因。人工价格、重量、采购成本、供应商报价、暂停状态、采集次数和采购交接记录保持原值。
- 与人工编辑和供应商写入共用串行保存队列，重新检查当前任务归属；归档任务不会被补算。结果未变化时不写文件、不重复推送。

验证使用采集器启动/巡检入口和隔离持久化任务，覆盖 127 件跨页商品、人工暂停、访问验证、缺失/无效输入、人工编辑并发、归档和重复巡检。

专项更新包适用于安装版 v0.9.63。先运行原安装目录的 Stop.cmd，解压补丁并运行 Install-Watchdog.cmd，选原安装目录，再运行原 Start.cmd。安装时校验版本和文件哈希，自动备份，保留 data/config；补丁自身不启动采集。
