# v0.9.55：有限补查与逐商品失败原因

旧版将成功读取页面但未完成重量、上架日期核验的商品直接结束为“字段缺失”，后续后台巡检不再补查。现在每次巡检会检查当前任务中明确可恢复的访问中断、超时和未完成的信息区检查；每件商品最多额外补查两次，分别冷却一分钟、两分钟，预算随断点保存，刷新或服务重启不会重置。已证实页面未提供的数据不重复访问。

候选商品旁和详情中显示具体失败原因，包括网络超时、信息区检查超时、重量值冲突、ASIN 不一致和访问验证，并显示补查状态、次数及最终耗尽原因。单次请求保留四分钟截止，迟到结果不能覆盖暂停或新任务。

重量核验修复两项实际页面问题：纯导航空锚点不再被当成尚未加载的商品信息面板；英制重量按显示精度换算并限制舍入容差，避免将 0.37 Pounds 与 170 Grams 误判为冲突。承载容量继续排除，真实矛盾仍保持未知。浏览器补读失败保留具体错误码，不能将未检查完成误报为页面没有提供。

部分页面同时展示当前变体的 Voyager 规格表和另一 ASIN 的旧版详情。仅当安全信息区明确列出当前 ASIN 且主商品身份一致时，解析器才整区排除另一 ASIN 的信息，保留当前商品的匹配区域；被排除区域的日期、重量等全部不可使用。排除证据保存在 `productInformation.discardedSections`。没有当前 ASIN 强证据、同一区域出现身份矛盾或主商品 ASIN 不符时仍拒绝采纳。

自动补查只作用于原任务已有商品，不新建任务、不扩大 ASIN 范围、不修改人工价格、重量、成本或供应商报价。人工暂停、1688 协调占用、验证码、登录失效和明确风控保持停止。`recheck` 只检查并使用剩余补查预算，不能替代人工 `retry_missing` 重置失败项。

## 本机验证结果（2026-10-14）

语法检查通过。全套测试中的功能测试通过；因沙箱权限失败的 Windows 平台用例在允许读取进程信息的隔离测试中复跑，33 项全部通过。最后补充的同区 ASIN 冲突回归覆盖五种布局，并经独立复核。

通过现有启动器加载 v0.9.55 后，原任务 `32351259-f509-4400-8030-8cc6e35249b9` 的 9 个 ASIN 保持不变，197 项人工输入、采购与供应商字段比对一致。1688 子任务、报价与执行次数保持不变；启动初始化刷新了汇总版本号和完成时间。

自动补查已触发，但 B0GVJBLRKF 的浏览器访问返回 `AMAZON_ACCESS_CHALLENGE`，任务正确转为 `needs_attention` 并停止请求，后续读取仍保持 revision=15、workerActive=false。未继续强制补采其他商品。原有四个 ASIN 身份异常仍待用户处理验证后重新核验，因此不能把本次上线报告为整批补采成功。页面已验证显示逐商品失败原因与暂停状态。诊断快照与对比结果位于 `.diagnostics/release-0.9.55-*.json`，界面证据为 `.diagnostics/release-0.9.55-failure-ui.jpg`。
