# 同事电脑安装与 WorkBuddy 接入

此包运行独立的本地 Scout 服务、任务执行器和进程守护。WorkBuddy、ChatGPT 或其他 AI 都只是可选入口。**安装后不需要 AI 定时发消息，也不需要把自动轮询再配置成 WorkBuddy 计划任务。**

## 1. 安装

适用 Windows 10/11 的 64 位电脑，电脑应已安装 Microsoft Edge 和 **Node.js 24.x（Windows x64）**。将交付的 ZIP 完整解压到本地目录，再双击根目录 `Install.cmd`，不要直接在压缩包预览中运行。使用正常同事账户安装；不要把自己的数据、密钥、登录 Cookies 或浏览器目录复制给同事。

这是轻量安装包：使用电脑已有的 Node.js，不附带 `node.exe`。安装器会检查 Node 为 24.x、Windows x64，并记录通过检查的可执行文件绝对路径供后台启动使用；不会替换全局 Node 或修改全局配置。程序所需的 npm 生产依赖和 1688 采购组件仍随包提供，安装时无需运行 `npm install`。

若检查提示版本或架构不符合，请先在本机准备 Node.js 24.x Windows x64 再运行安装器。安装完成后不要移动或删除已记录的 Node 可执行文件；若 Node 安装路径改变，应重新运行安装器完成检查和路径登记。安装位置为：

```text
%LOCALAPPDATA%\ScoutAmazon\
  app\          程序与 1688 桥接依赖
  interfaces\   OpenAPI 定义及 PowerShell 接口脚本
  docs\         安装与业务说明
  data\         当前任务、历史结果和巡检去重记录
  config\       本机可选 SellerSprite 配置
  logs\         程序和安装层运行日志
  exports\      本安装包导出的任务文件
  control\      安装和登录自启的控制脚本
```

本安装包的路径与启动方式以本说明为准。附带源码文档里的旧 `D:` 盘路径、项目内 `data` 路径和源码启动步骤不适用于此安装版；不要为同事电脑照搬这些旧路径。

首次安装会启动程序并打开网页；安装器配置当前用户登录后启动，此后登录只启动服务、不自动弹出网页。这是**登录自启**，不是用户登录前的系统服务。安装器不会代同事登录 Amazon/1688，也不会替同事配置 SellerSprite。

安装目录根部的 `Start.cmd` 用于启动，`Stop.cmd` 在任务已经暂停或空闲时停止本安装服务，`Uninstall.cmd` 先按相同规则停止，再撤销本安装的登录自启和快捷方式。卸载默认保留安装目录及全部数据，不自动删除历史记录。桌面快捷方式为 `Scout Amazon <安装标识>.lnk`，标识用来区分不同安装。关闭 AI 或浏览器不等于退出后台服务。

安装后打开 <http://127.0.0.1:4173/>。如果端口被其他服务占用，先查明来源，不要终止不属于本程序的进程。

## 2. 第一次使用

1. 导入同事自己的店铺文件，并在界面建立一个新批次。站点以导入链接为准，加拿大店铺使用 CA。
2. 无 SellerSprite 时保持接入开关关闭，直接使用 Amazon 模式。不要因为未配置 MCP 而尝试授权或重复连接。
3. 需要 1688 时，采购组件已随包提供；首次使用在界面打开本人登录页面，用本机 Edge 完成账号登录即可。只有用户确认的候选商品进入匹配。
4. 在“后台巡检”区域确认监控运行；也可一次性执行接口脚本的 `-Operation Status`。`configured:true` 表示配置启用，`enabled:true` 才表示实际运行，错误字段非空要排查。

Amazon 页面没有月购买量时标记未知，不当作零，也不保证能从页面获得每个商品的精确月销量。SellerSprite 连接成功、商品工具调用次数、有效月销量 ASIN 数是三个不同指标。

## 3. 自动轮询实际由谁执行

| 组件 | 默认频率 | 负责的行为 |
| --- | --- | --- |
| Amazon 后台执行器 | 每 30 秒检查 | 已保存批次推进、断点、有限重试 |
| 1688 后台执行器 | `nextRetryAt` 到期唤醒，每 5 秒兜底检查 | 已确认的产品匹配、排队和冷却；不是每 5 秒发一次搜图 |
| 安装包进程守护 | 每 60 秒检查 | 通过版本/runtime 只读检查，确认归属后恢复退出服务；Scout 无响应连续 3 次或可运行任务 15 分钟无进展时复核恢复。每个服务每小时最多启动 5 次，次数持久保存 |
| Amazon 事件巡检 | 每 15 分钟 | 完成、持续故障、恢复和需人工操作的事件记录 |
| 1688 事件巡检 | 每 30 分钟 | 验证暂停、速率试验吞吐不足、实际试验完成等事件记录 |

事件巡检只读任务和原生桥接状态，不调用任何 `health` 接口、不带 `verify`、不授权 SellerSprite、不主动解除人工暂停。安装版记录保存在 `data\scout\program-monitor.json`，界面和 `GET /api/monitor` 读取缓存；正常、冷却、等待、重复状态不会反复产生异常通知。服务恢复和业务推进由执行器、守护器处理，不需要等 15/30 分钟的事件巡检。

## 4. 哪些中断能恢复，哪些要本人处理

| 情况 | 行为 |
| --- | --- |
| 主服务或 1688 桥接意外退出 | 守护确认属于本安装后有限恢复；Amazon 按保存状态处理，1688 遗留 running 等待明确继续，不另建批次 |
| 服务进程仍在但持续无响应 | Scout 连续 3 次版本请求失败后再次确认进程与端口归属，替换本安装进程；1688 桥接仍仅记录。达到每小时上限后等待窗口到期 |
| 短时网络错误或缺字段 | 按原程序有限重试和冷却，不无限重试 |
| 人工暂停 | 保留任务、结果、人工数据及断点，等待用户明确恢复 |
| 上传新文件 | 文件验证有效后才取消并归档旧任务；无效文件不会取消旧任务 |
| Amazon/1688 验证、滑块、登录失效 | 保留断点，用户在本人浏览器完成处理后明确恢复；不会自动破解或强行续跑 |
| 电脑关机、休眠、断网 | 当时无法采集；重新登录并恢复网络后按保存状态处理，不能保证永不中断 |
| 1688 尚未登录 | Amazon 模式可继续；在本机 Edge 完成本人的 1688 登录后再匹配 |

关闭网页后，Amazon-only 采集和已确认的 1688 后台匹配可继续。**SellerSprite 多店铺、多批次分析仍由网页逐批请求，执行期间需要保持页面打开**；本次安装包不把该流程伪装为完整后台队列。关闭后需本人明确继续。

1688 搜图速率及冷却以桥接 `ratePolicy` 为准。安装不启用新的速率试验；已有人工配置照其自身规则运行。一次未出现验证不代表平台固定安全阈值，样本不足或观测中断不能算通过。

## 5. 可选 SellerSprite

没有 SellerSprite MCP 的同事直接使用 Amazon 模式即可。需要 SellerSprite 的同事使用自己可用的凭据；Scout 直接连接官方 MCP，不要求先安装到 WorkBuddy 或 ChatGPT，也不读取 AI 客户端配置。

将安装目录中 `config\sellersprite.example.toml` 复制为同目录 `sellersprite.local.toml`，按示例配置。安装启动入口通过 `SCOUT_SELLERSPRITE_CONFIG_PATH` 指向此文件。使用环境变量密钥时，它必须在启动程序的进程环境中可用；若刚修改用户环境变量，应退出后台后重新启动，使新环境生效。

配置后在网页主动开启接入、连接当前店铺站点。不要将密钥粘贴到 WorkBuddy 提示词或接口定义中。更多配置形式见 [独立运行说明](standalone-operations.md)。

## 6. WorkBuddy 的接口文件

安装目录 `interfaces` 包含 `scout-local.openapi.json` 和 `Invoke-Scout.ps1`。前者是标准 OpenAPI 3.1，后者是可由本地命令工具执行的 PowerShell 客户端；本包不假定 WorkBuddy 专有导入格式。

一次性检查：

```powershell
& "$env:LOCALAPPDATA\ScoutAmazon\interfaces\Invoke-Scout.ps1" -Operation Status
```

接口只提供状态与用户明确的当前任务暂停/恢复，控制必须提供真实 `runId` 和客户端 `-Confirmed`。不提供自动新建、归档、清空、改速率或授权接口。操作范例与可直接交给 WorkBuddy 阅读的边界见 [接口使用说明](../interfaces/README.md)。

本服务只监听 `127.0.0.1:4173`；POST 必须携带精确 `Origin: http://127.0.0.1:4173`。`localhost`、外网地址和任意查询参数不作为替代。云端 AI 的 `127.0.0.1` 不指向同事电脑；需要 WorkBuddy 的本地执行能力，不开放公网端口。

## 7. 排障、升级和迁移

先看一次 `Status`，再看安装目录 `logs` 的错误日志与界面提示。未配置 SellerSprite 与主服务故障是两回事；未准备 1688 与 Amazon 采集也分开排查。接口读取报错时不要循环提交启动/恢复命令，尤其不要调用健康/验证/授权接口“试通”。

升级前先暂停正在执行的任务，并备份本机 `data`、`config`、`exports`。业务数据与程序目录分离，程序替换不能用打包者的数据覆盖同事数据。迁移本人的 1688 登录环境应按浏览器和公司的账户安全流程处理，不把个人 Cookies 放进共享安装包。

暂停按钮不删除业务数据；卸载或清理前确认是否需要保留历史记录和人工价格、重量、采购成本、供应商报价。不要用删除 `data` 的方式处理卡住或等待验证码的任务。

## 本次中断修复与数据格式

1688 重启时发现未完成的 running 搜图，将保留任务并标记执行中断，等待用户检查后明确继续，不自动重复提交。大任务改用分区存储，备份必须包含任务 JSON 和同名 `.json.parts` 目录；下载任务仍为完整独立 JSON。详见 [暂停与中断恢复说明](task-recovery.md)。
