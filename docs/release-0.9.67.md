# 0.9.67 — 按有效规格选择最高 FBA 费用，并降低采集频率

2026-10-20，保留版本号 0.9.67，汇总本地更新并同步 GitHub。

商品页继续分别记录 Item Weight 与包裹重量。Product details、Product information、Item details、Measurements 的结构化字段沿用单页访问策略，不因重量或日期缺失强制展开额外面板。

商品重量、包裹重量和尺寸分别记录，三项均缺失时才提示规格信息不完整。加拿大体积重（kg）= 长 × 宽 × 高（cm）÷ 5021.69；分别计算商品重量、包裹重量和体积重对应的 FBA 费用，采用最高费用用于利润，并标注实际依据。仅有尺寸时允许体积重暂估，实重保持未知。澳洲暂不以体积重选费，只比较已有实重对应的费用；仅有尺寸时仍待计算。

已有实重的国内运费和头程继续采用商品与包裹重量中的较大值；只有一种有效实重时使用该值，同重优先标记 Item Weight。人工重量和人工 FBA 费用保持优先。包裹重量必须有页面字段、原文、ASIN 和数值匹配的证据，不能从旧计费缓存猜测。体积重作为独立估算值，不写入实重观察。

Package/Parcel Weight、Shipping Weight 以及 Package/Parcel Dimensions 中带明确单位的重量均保留为包裹重量。截图所示 `Parcel Dimensions: 16.5 x 15 x 1.9 cm; 60 g` 为 0.06 kg 包裹重量，不能写入 Item Weight；纯尺寸、承载能力和推荐商品不提供重量。

结果卡片、详情、FBA 来源及利润说明显示所选来源。审核表重量列改称“利润计算重量 (kg)”，末尾新增“重量来源”，保留原日期和费用列顺序。分析导出独立保留 item_weight_kg、package_weight_kg，并携带计算重量来源。

采集审计接受有证据的包裹重量，避免仅因没有 Item Weight 重复访问。保留现有任务、原始观察、人工价格/成本/重量、供应商报价与补查预算。

回归覆盖截图的 60 g、四个详情区域、40/60 g 与 80/60 g 比较、同重、单位、缺重、无证据缓存、人工覆盖、前后端利润、表格和分析导出。

Amazon 页面请求最小间隔提高 50%：默认 2100 ms、加拿大 1800 ms、德国及巴西 4500 ms；后台详情并发降为 1，交互详情默认并发降为 2。按用户后续确认，1688 普通队列调整为每 60 分钟最多 70 次，启动间隔至少 51.429 秒、并发 1，不再每 10 件额外休息；独立速率试验、平台限流及验证暂停维持原规则。
